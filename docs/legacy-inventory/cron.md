## Modern Scheduler Registry

The new Laravel workspace now has a read-only ingestion registry and dashboard:

- Dashboard: `/ops/ingestion`
- Job detail: `/ops/ingestion/{jobKey}` with due/next-run preview and read-only execution guardrails
- Local one-shot runner: `POST /ops/ingestion/run`, exposed from the dashboard and recorded under Laravel local storage as `ingestion-runs/*.json`
- Registry: `config/ingestion.php`
- Console view: `php artisan ingestion:list`
- One-shot dry-run: `php artisan ingestion:run`
- Scheduled/local history: `php artisan ingestion:run --record` writes the same JSON record format shown at `/ops/ingestion/runs/{runId}`; the Laravel scheduler uses `ingestion:run --execute --record` only when `INGESTION_SCHEDULER_ENABLED=true`
- First read-only local commands: `php artisan youtube:channels:stats`, `php artisan youtube:channels:videos`, `php artisan youtube:tvbs:videos`, `php artisan youtube:live:poll`, `php artisan youtube:tvbs:live:poll`, `php artisan youtube:live:cleanup`, `php artisan youtube:videos:duration`, `php artisan youtube:videos:stats`, `php artisan youtube:comments:queue`, `php artisan youtube:comments:fetch`, `php artisan ai:daily`, `php artisan ai:hourly`, `php artisan reports:live:show`, `php artisan reports:live:build`, `php artisan reports:live:clean`, `php artisan reports:live:static`, `php artisan reports:static:build`, `php artisan reports:mayor:static`, `php artisan reports:counts:build`, `php artisan reports:groups:build`, `php artisan reports:keywords:build`, `php artisan reports:people:build`, `php artisan reports:schedule:build`
- Activation guardrails: see [scheduler-activation.md](scheduler-activation.md) for the env flags, rate limits, locks, retry policy, API quota handling, and local-vs-production separation required before any write-capable scheduled polling.

Current update: scheduled write/API execution now requires a capped `scheduled_execute_command` plus `INGESTION_LOCAL_POLLING_ENABLED=true` and an exact allowlist; production additionally requires `INGESTION_PRODUCTION_POLLING_ENABLED=true`. `ai:hourly --execute` calls OpenCode-compatible chat completions and idempotently upserts `urt_ai_hour`; dry-run remains the default.

`INGESTION_SCHEDULER_ENABLED` defaults to `false`. The registry documents legacy cron parity, proposed Laravel command names, schedules, external dependencies, and write targets, but it does not start external polling, AI generation, production writes, or migrations. `ingestion:run` is dry-run by default and only reports due jobs. Actual scheduler execution requires `--execute`, enabled scheduler config, an `active` registry status, an existing Laravel command, and a read-only execution profile. The dashboard one-shot form uses the same runner and temporarily enables execution only for that request; it writes only a local JSON run record and never changes the global scheduler setting.
