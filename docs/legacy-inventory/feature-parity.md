## Recommended Build Order

1. Revisit channel and video comment/cloud/trend subpages when local dumps include more complete `urt_comment`, `urt_show_cloud`, and `urt_log` rows.
2. Import or expose a read-only `urt_ai_period` dump so the implemented AI event history tracer can render production-like multi-day chains locally.
3. Consider a smaller read-only comment dump before upgrading video/channel comment analytics beyond unavailable state.
4. Expand more local-only derived report commands after the implemented `youtube:*`, comment, and `ai:hourly` execute paths prove stable; derived cache-write semantics still need per-command execute design.
5. Promote production polling by setting deployment-side scheduler/production flags, exact allowlist, daemon supervision, and backup/rollback evidence.
6. Rebuild comment queue/ingestion after live/video entities are stable and comment quota behavior is designed.
7. Migrate legacy API consumers to clean URLs last, keeping compatibility redirects until replacement consumers are known.

## API Compatibility Notes

- `api/api_live_day.php`: read-only JSON from `urt_video_live_log`, preserving `videoId`, `date`, `from`, and `to`.
- `api/api_live_date.php`: read-only JSON; uses `urt_show_live_date.return_json` when cached locally and derives from `urt_video_live_log`, `urt_show_video_live`, and `urt_count` on cache miss without inserting/updating cache rows.
- `api/api_live_hour.php`: read-only hourly peak map derived from `urt_video_live_log.log_json`; no `urt_show_live_hour` cache writeback.
- `api/api_live_tag_date.php`: read-only cache reader for `urt_show_live_tag_date`; preserves sorted `tagid`, `or`, `not`, and `date` lookup semantics, and unwraps legacy cache columns like `tags_views`, `tags_video`, `hour`, and `data`. Cache misses return empty result structures plus metadata instead of triggering legacy background generation.
- `api/live_date.php`: read-only filtered live video list from `urt_video_live_log`, `urt_show_video_live`, and `urt_count`; supports legacy tag filters, date/range, sorting, and limit without cache generation.
- `api/live_tvbs.php`: read-only JSON shell over `urt_video_live_log_tvbs`; local dump currently has no rows, but the compatibility route is present and tested.
- `api/video_live.php`: read-only HTML snippet using `urt_video_live.concurrentViewers` and `urt_video_live_log` sparkline data.
- `api/csv_live_line.php`: read-only CSV export of hourly live peaks for one `videoId`.
- `api/tags_list.php`: read-only tag id/name map from `urt_tag`.
- `api/tags_index.php`: read-only keyword index from local `tags`, including legacy-style computed weight.
- `api/tags_all.php`: read-only cache reader for `urt_show_data.data_name='tags_all'`; accepts direct/wrapped/list-shaped metric payloads, and local cache misses return unavailable metadata instead of running legacy force regeneration.
- `api/video_tags.php`, `api/video_tags_title.php`: read-only keyword extraction for one video. Cache tables are read first; if empty, keywords are computed from local `tags` without inserting/updating `urt_show_video_tag*`.
- `api/channels_list.php`: read-only channel list using legacy `tagid`, `or`, and `not` filters from `urt_count`.
- `api/channel_videos.php`, `api/channels_videos.php`: read-only recent video APIs from `urt_video`, preserving `u_id`, tag filters, `hours`, `min`, `limit`, and optional comment shell behavior.
- `api/api_channel_log.php`: read-only expansion of `urt_log.thedata` into daily video delta, raw view delta, prediction, and seven-day moving average. Local `urt_log` currently has 0 rows, so production-like calls return a zero series with unavailable metadata instead of triggering polling.
- `api/channel_pred.php`: read-only prediction summary over recent `urt_log` rows; the legacy `urt_count.views_pred_week/month` update is intentionally omitted.
- `api/api_tag.php`: legacy bare JSON tag map from `urt_tag`.
- `api/api_tag_log.php`: read-only `urt_log_tag` aggregator. Local dump currently has 0 rows, so most calls return unavailable metadata.
- `api/tags_day.php`, `api/tags_video.php`: read-only `urt_show_tag_cloud` cache readers with map/list/wrapped keyword-weight parsing; cache misses do not insert cache rows or trigger background generation.
- `api/tags_relation_date.php`: read-only `urt_show_video_tag_date` cache reader with map/list/wrapped `tags_json` and `videos_json` parsing.
- `api/tag_month.php`, `api/tag_period.php`: read-only `urt_show_tag_month` cache readers with direct/wrapped date-metric payload parsing.
- `api/tag_tags_days.php`: read-only `urt_show_tag_cloud_tag` cache reader with direct/wrapped `tags_result` and `videos_json` parsing.
- `api/cloud.php`: read-only channel cloud cache reader from `urt_show_cloud`; accepts map/list/wrapped payloads, and local cache misses return unavailable metadata instead of inserting a cache row or background-calling legacy PHP.
- `api/cloud_tag_date.php`: read-only `urt_show_tag_date` cache reader; preserves sorted `tagid`, `or`, `not`, `date`, and safe `type` selection across `tags_result`, `tags_video`, `tags_views`, and `all`, with map/list/wrapped payload parsing.
- `api/cloud_tag_date_noapi.php`: read-only `urt_show_tag_date` compatibility shell for the older tag-date cloud endpoint; parses map/list/wrapped payloads, and cache misses do not insert or schedule generation.
- `api/group_view.php`: reads `urt_show_group.the_result` if a local cache table is present; when missing locally, returns a read-only membership shell from `tag_group` plus legacy group-view definitions and marks trend matrices unavailable.
- `api/ai_day.php`: read-only daily AI JSON from `urt_ai_date` plus per-channel `urt_channel_ai`, preserving `date`, `condition`, `pk`, `from`, and `to` lookups.
- `api/api_topic.php`: read-only topic/video cache reader from `urt_ai_date.data_json` and `video_json`; when cache is absent, derives a lightweight topic summary from list or wrapped `events`/`topics`/`result`/`data` `result_json` variants without updating the cache columns.
- `api/api_event.php`: read-only current event match shell from `urt_ai_date` plus legacy `urt_ai_period.result_json` match-chain expansion and `data_json` pk mapping when rows exist. The `prefetch` branch intentionally returns empty keyword shells instead of calling `api_topic.php`; local `urt_ai_period` currently has 0 rows, so production-like history remains marked unavailable.
- `api/api_comment.php`: read-only `urt_comment` reader; the legacy `urt_log_api` insert is intentionally omitted.
- `api/api_duration.php`: read-only plain-text duration lookup from `urt_video_duration`; cache misses return `0` and do not insert duration queue rows. Queue processing is separately previewed by `youtube:videos:duration` without calling YouTube or updating `urt_video_duration`.
- `api/api_get_photo.php`: read-only plain-text photo URL lookup from `urt_show_photo`; cache misses return `null` and do not call Wikipedia or insert cache rows.
