## Remaining Operator Or External Follow-up

The items below do not represent scaffolded Laravel features:

1. Production polling or allowlist changes require explicit operator approval, exact dry-run evidence, a current backup, and a rollback plan.
2. Production-like local report depth still depends on approved data exports for sparse historical tables such as `urt_ai_period`, `urt_comment`, `urt_show_cloud`, and `urt_log`.
3. YouTube and AI execute smokes require locally configured credentials and available provider quota; Wikipedia photo refresh requires outbound access to `zh.wikipedia.org`; commands fail safely when their external dependency is unavailable.
4. Manual keyword-relation, keyword-cloud, live-tag-date, tag-month, and photo cache builders remain intentionally unscheduled until a separate Production schedule and allowlist review is approved; tag/channel cloud and tag-date builders have separate active capped registry jobs.
5. Legacy API consumers can migrate to clean URLs after replacement consumers are known; compatibility routes remain covered in the meantime.
