# Scheduler Parity

Ground truth is `/Users/sky/Documents/youtube-board-legacy/urtube/cron` plus the standalone `maint/*.php` scripts. This file tracks the legacy scheduling and write semantics against Laravel commands. Public `https://youtube.board.tw` behavior is secondary only.

Safety defaults:

- `INGESTION_SCHEDULER_ENABLED=false` by default.
- `php artisan ingestion:run` is dry-run unless `--execute` is supplied.
- Registry-driven scheduler execution normally runs read-only command defaults; allowlisted jobs with `scheduled_execute_command` run capped command-level flags such as `--execute`.
- Scheduler-enabled local polling is available only when `INGESTION_SCHEDULER_ENABLED=true`, `INGESTION_LOCAL_POLLING_ENABLED=true`, and the job key is present in `INGESTION_SCHEDULED_WRITE_ALLOWLIST`; then the runner uses the job's capped `scheduled_execute_command`.
- Commands that can write must print their write targets and must keep dry-run as the default.
- Secrets are checked through env/config and are never printed.
- Activation and promotion rules are documented in [scheduler-activation.md](scheduler-activation.md). Manual local `--execute` smokes are not scheduled write polling; scheduled write-capable jobs require allowlist, locks, rate limits, quota handling, and local/production safety gates.

## Activation Design

See [scheduler-activation.md](scheduler-activation.md) for the detailed activation model. Current implementation supports dry-run previews, scheduled read-only jobs, manual local-only `--execute` smokes, and allowlisted capped scheduler execution for jobs with `scheduled_execute_command`. Production activation still needs deployment-side env changes, backup/rollback evidence, and daemon supervision outside this local workspace.
