# Public author-comment report

`/api/v1/comments/authors/:key` and the corresponding Next page show paginated public comments plus a Taipei 24-hour main-comment/reply matrix, per-channel totals, and the legacy selected channel-taxonomy distribution (IDs 3, 4, 5, 6, 48, 49). Aggregates cover the complete indexed history independently of comment pagination. As in Laravel, `hours` is a compatibility field, not a time filter; the report says this explicitly. Pagination follows the new API-wide default 50 / maximum 200.

Only reverse-indexed `urt_comment` rows with empty or NULL pageToken are published. Author ChannelId and video IDs compare byte-exact; replies in arrays or maps are counted once. Missing dates are counted separately and excluded from the hourly matrix. The bounds are 5,000 indexed video IDs/batches and 100,000 matched comments, with explicit rejection rather than silent truncation. These bounds are implementation limits, not claims of complete YouTube coverage.

Channel rows include only channels with matched comments. As in Laravel, their indexed-video count includes all complete indexed batches for that channel, even if an indexed batch no longer contains the author. Taxonomy counts use those indexed videos, including channels with no remaining matched comments. Multiple taxonomy memberships overlap; duplicate tags within one channel are deduplicated. This is channel taxonomy, never the maintained tag.observe.tw content vocabulary. Tied taxonomy rows use deterministic ascending ID order (Laravel preserved incidental insertion order).

Current ingestion writers produce string-list reverse indexes. Readers also accept legacy value maps; scalar values are trimmed and numeric list values become strings. A deliberate extension preserves earlier TS support for `{videoId: numericCount}` maps with an 11-character video key: the key identifies the video, whereas Laravel's scalar-first parser would interpret the count as its ID. That extension is disclosed in the response notes when used. Invalid entries are counted in report metrics; invalid string values do not fall back to unrelated object keys.

Validation includes actual isolated MariaDB fixtures for byte-exact indexed IDs, unfinished-batch exclusion, full-history aggregates independent of pagination, overlapping taxonomy, explicit lookup aliases and parameter errors, plus offline parsing/hourly tests. No production data was inspected. An actual CLI Proxy Opus 5.5 review is recorded locally at `.local/reviews/groups-author-review.json`; its concrete findings informed parser tests, PHP-compatible group-name whitespace scope, truthy legacy-sync rejection, and documented intentional differences. Group CLI DB verification uses the same `connectDatabase` function as CLI, including `dateStrings: true`.
