# Stored channel AI reports

These routes only read existing database output. They never run inference, schedule generation, or claim that model descriptions are objective political identities.

- `/channels/:id/ai`: independently selects the latest non-deleted `topic`, `people`, and `aspect` rows with result length greater than 10 bytes, retaining each source's own period, model label and exact-record citation. Topic descriptions/strength, people roles/evaluations/scores and grouped aspect descriptions/scores are rendered. Source availability and item counts are distinct; a stored record need not contain a displayable item. The original static prompting suggestions are replaced by a link to the reviewed, read-only prompt preview.
- `/channels/:id/ai/days`: defaults to the latest visible daily date; `date` selects a specific end date, optional `days=1..90` expands the date window. `oneday` and `todate` share the midnight start and highest PK wins for that start, matching Laravel daily selection. `type=week` reads the latest stored weekly record, never synthesizes one from daily results. The recognized types are `oneday` and `week`; unsupported types and incompatible filters return 400.
- `/channels/:id/people`: `oneday` only, latest PK per exact start/end interval, default 28 days, maximum 90. The full 31-name presenter/guest/generic-label exclusion list is retained. Default page size is 10, maximum 30; the matrix follows the current ranked page. Every observed-day cell includes both topic mentions and video-reference counts. Missing source dates remain null, while observed zero references can still accompany unreferenced mentions.

Existing `/ai?date=...`, `days`, or `type` links retain the daily-view behavior. An exact `pk` citation is channel- and report-family-scoped; it cannot be mixed with date/days/type. Deleted and mismatched-channel sources are never selected. Overview sources use `/ai?pk=...`; daily/weekly sources use `/ai/days?pk=...`.

Automatic daily/people anchoring examines the newest 90 candidate periods and chooses a date with visible, parseable output. Coverage exposes whether that search was truncated and how many newer unavailable sources were skipped. Explicit dates retain empty/unpublished states instead of silently substituting another day. People aggregation preserves Laravel's exact-period grouping: multiple different period endings on one date can contribute separately.

Publication uses indexed SQL `EXISTS` per selected source, not an arbitrary cap on historical run headers. A byte-identical output targeted by an unpublished TS run is withheld; null-target same-key/exact-output runs are also conservatively withheld because the writer can insert a projection before recording its PK. A validated run targeting a legacy PK with **different** output does not hide the unchanged legacy row: the writer records that target before its UPDATE. Published replacements at another PK do not erase old exact citations. Citations show when the selected period/type has a newer row.

A target previously published by TypeScript whose current output no longer matches any published result is separately classified as `divergedSources` and withheld. Under the exclusive-writer handoff policy, it must not silently be reclassified as Laravel output. This is a deliberate conservative integrity decision, not a claim that its content is unpublished. The matrix and `sourceAvailability` distinguish pending, divergent, malformed, missing and partial dates. Availability uses stable `observed | partial | pending | diverged | malformed | missing` codes with separate labels and all applicable reason codes, including multiple unavailable periods on one date. Overview and explicit date selections do not fall back to older revisions when the latest source is unavailable; automatic date selection can choose an earlier visible date with explicit coverage.

Publication comparison converts journal text to utf8mb4 before hashing. Four-byte output is regression-tested. These checks verify current-output publication, not complete immutable generation-input provenance. No matching journal is labeled simply “無 TypeScript 發布紀錄”, not inferred to be imported data.

Video-reference links use the result's valid 11-character IDs and current local channel ownership. SQL combines an indexed candidate-ID predicate with a byte-exact residual predicate, and JS retains exact identities; case variants remain distinct. Missing, cross-channel, or ambiguous duplicate video IDs are disclosed and unlinked. These counts do not prove source completeness at generation time. Duplicate IDs within a topic and repeated names within a topic are normalized; the same video cited by different topics can still count repeatedly. Unlike Laravel's `max(1, refs)` approximation, an unreferenced topic does not invent a video count. Numeric score decimals are retained rather than rounded to integers; missing/blank/boolean scores are null.

Read bounds: 400 source periods, 16 MiB selected result payload, 10,000 parsed topic rows, 5,000 distinct video IDs and 20,000 rendered references. Overflow is an explicit error, not a partial count. These are operational limits, not claims of upstream capture completeness.

Generic report sections have stable keys: `people`, `aspects`, `sources`, `reports`, `references`, `people-matrix`. Channel profiles reuse the same helpers rather than implementing a second source-selection policy. Their optional overview/daily blocks independently catch only `ChannelAiBoundError` and a specifically identified missing `ts_ai_runs` publication sidecar. Normal blocks use `evidenceCoverage.status = available`; degraded blocks preserve the same coverage keys with unknown values null, user-facing notes and `status = bounded | unavailable`; core channel/video data remains HTTP 200. Missing-sidecar detection is confined to the query referencing only that table. Unknown-column and other SQL/schema failures remain HTTP 500; connection failures retain their normal unavailable classification. Invalid user queries are not swallowed. Standalone report routes retain the API query-bound HTTP 400 contract for selections exceeding read limits; this is explicitly regression-tested. Profile enrichment catches only those known bound errors, not invalid user queries.

Validation: focused API tests include legacy shape normalization, all presenter exclusions, separate overview periods, exact daily/week citations, latest todate/oneday selection, inactive rows, byte-exact video IDs, missing/cross-channel references, missing-day null vs unreferenced mentions, automatic anchor selection, same-key failed journals, null-target publication gaps, result divergence, channel-profile integration, strict filters, wrong-channel PK refusal, target-before-update failure, more than 2,000 historical attempts, four-byte Unicode, and both directions of optional profile degradation versus unknown-column 500, and actual createReader handling of MariaDB missing-table 1146. The focused channel-AI plus existing database regression run passed 40/40 with real isolated MariaDB on 2026-10-12. Actual CLI Proxy reviews are stored locally in `.local/reviews/channel-ai-review.json` and `.local/reviews/channel-ai-followup-review.json`; the final targeted corrections/optional-block review is `.local/reviews/channel-ai-final-review.json` (only returned text counts as review evidence). No production data was inspected or changed.
