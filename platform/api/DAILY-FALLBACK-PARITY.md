# Daily source fallback and regrouping

`readAiDaily` reads stored daily summaries first. For an explicit date without a summary, it can group the latest eligible per-channel records for that exact Taipei calendar day. The unfiltered `all` index inspects at most90 recent candidate channel records (plus one truncation sentinel), with a lower bound at the existing cache date. It adopts a newer full-day window only if publication-checked source grouping yields topics. Newer withheld/malformed/empty sources or optional capacity failures preserve the existing stored anchor and report the reason; the candidate search truncation flag is explicit. A full-day source window does not imply complete video coverage. Other condition indexes keep the stored daily anchor; explicit dates support all condition scopes.

Selection and provenance:

- Exact `pk` and explicit stored `type` are stable reads, never source regroupings. Every TypeScript daily lineage state also disables regrouping: valid immutable snapshots retain generation-time sources; pending/damaged/divergent snapshots do not fall back to mutable sources.
- Sources use the highest nondeleted PK per channel and exact interval, with null/oneday/todate types for fallback. Active local channel identity is required. Classification uses EXISTS/NOT EXISTS rather than a count-table join, so extra count rows cannot duplicate source records. The shared publication guard withholds pending, diverged or malformed results without reverting to older channel revisions.
- Conditions retain Laravel channel taxonomy: green4, blue3, finance31, world41, neutral excludes3/4/5/6/31/41, other allowed condition names remain unrestricted. These historical channel categories are not new inferred political labels.
- Source PK plus event item index are retained for regrouped evidence. Same-name channels remain distinct IDs. Cached name references resolve only a unique channel and a unique event title; ambiguous references remain unresolved.
- Mutable source video citations are checked by byte-exact ID, unique local row and channel membership. Unknown/mismatched syntactically valid IDs remain visible as unlinked references, never silently assigned to a different video. Invalid-reference counts are retained per evidence item and in coverage. Immutable snapshots preserve their original references and explicitly identify that evidence scope.

Regrouping ports Laravel's deterministic rule: normalize title/keyword/person signals, exclude the exact weak-token list, and join only on at least two strong shared signals. Entry order uses valid deduplicated source references before greedy clustering, so invalid/duplicate input can deliberately change both grouping order and ranking compared with Laravel. The highest-overlap cluster wins; ties preserve first-cluster order. This is signal grouping, not model inference or verification that reports cover the same event. Headline remains an actual source event title. Groups qualify with at least two channels or two distinct syntactically valid referenced video IDs; missing/invalid/duplicate IDs cannot invent evidence. Syntax-valid source citations can be absent in the mutable local video table and remain explicitly unlinked; qualification does not treat local cache incompleteness as proof a source reference is false. Derived sorting uses distinct referenced IDs + three per distinct channel; this deliberately corrects Laravel duplicate-reference inflation. Cached topics retain their stored-reference occurrence count; caps are40 for all,25 otherwise. No category-only synthetic topic is needed: Laravel's category branch is unreachable when nonempty event entries yield clusters.

A legacy cache is reconsidered when topic count is outside5–40(all)/3–25(other), or a majority has only one channel. Replacement uses Laravel's lexicographic count/cross-media quality rule with resolved distinct channel IDs for both sides (a deliberate correction to cached unresolvable-name inflation); a small one-topic fallback cannot erase a larger8/45-topic cache. Stable snapshots and PK reads bypass replacement entirely.

Regrouped topics use date+fragment links, never fabricated `/events/0` pages or cached-PK permalinks. The response dailyId is null, replacedDailyId is separate coverage metadata, and freshness only reflects the selected channel sources. Stored topics retain their existing links. The UI identifies source regrouping, exact channel-summary links and unverified local video references.

Bounds:400 selected sources;1MiB each and16MiB total (SQL suppresses payload bytes before transfer beyond limits);2MiB stored daily result and128KiB channel map;2,000 grouping entries;128 signals per event;5,000 unique videos and20,000 references for expanded citation lists; larger stored/snapshot reports retain titles, counts and source records but withhold video lists with explicit counts and reference-capacity coverage. A too-large local identity lookup leaves source IDs unlinked. Channel maps over400 preserve cache content while disabling optional source loading. JSON depth32/node100,000 bounds stop pathological nested payloads. The inverted signal index avoids scanning every cluster for every event. Capacity failures return422 when no usable stored result exists; known optional enrichment/regroup capacity failures preserve a stored result and report explicit capacity coverage. Unexpected SQL/schema errors still propagate. Immutable run input is bounded to16MiB and becomes snapshot-unavailable if larger. Schema/connection errors retain existing500/503 handling.

Coverage distinguishes composition/reason, withheld/diverged/malformed sources, reference scope and linked/unlinked citations. Immutable snapshots do not count the current video table (rawVideoRows=null). Mutable raw counts explicitly describe the current table for selected summary channels and the source period; they are not an all-YouTube coverage ratio. No read request calls an AI provider, writes a cache or changes ingestion ownership.

Tests: `daily-grouping.test.ts`, `daily-fallback-database.test.ts`, existing immutable-lineage and database suites. Actual Opus packets/reviews/resolutions reside outside git in `.local/reviews/daily-fallback-*`.
