# Stored event presentation and source-local aliases

The event detail reader presents stored summary facts/opinions, people and media classifications with source analysis IDs, full cited video lists, model-attribution notices and raw analysis access. It never invokes inference or mutates source data. Media classification is an AI description, not a verified political stance.

Identity remains explicit: `/ai/events/:id` without `event` means the actual event-analysis PK. That exact prompt revision is pinned even when a newer one exists. `/ai/days/:id/events?event=...` means daily PK plus title; the historical `/ai/events/:id?event=...` compatibility route keeps the same daily-PK meaning. Latest-per-type selection is byte-exact for title, prompt type and token and scoped to the selected source condition/token/dates. Direct event-PK siblings use the direct row scope; mismatch with the current daily row is disclosed and suppresses topic linkage. Older legacy event PKs remain readable when only a newer revision has a published journal. Missing/latest unpublished results do not fall back to older revisions.

When neither an exact title analysis nor exact topic exists, a title can resolve only through one exact source-event reference within the selected daily record. Ambiguous aliases or duplicate canonical targets return409. Unavailable daily lineage cannot establish aliases. No cross-day, fuzzy title or shared-keyword identity is inferred. Canonical aliases are exposed in `resolution`, including source daily ID and topic IDs.

TS event analyses require an exact published output plus verified immutable input hash, run identity, business key and source metadata. Pending, diverged, malformed and unavailable snapshots are counted separately and withheld. A valid historical snapshot can remain visible after the daily row changes: `sourceChanged` is explicit, its original video titles/citations remain preserved, current topic links are withheld, and incompatible source versions are excluded. A current-day alias cannot select an analysis generated from a different source revision. Legacy analyses are explicitly labelled `legacy-unrecorded`.

The structured contract contains summary events with facts/opinions, people grouped as supporting/opposing/other, and media grouped identically with main subject and all-media list. English/Chinese stored field aliases are normalized. All exact11-character, case-distinct references remain represented. Invalid, missing or out-of-snapshot media/video pairs are shown without links. Current local video resolution uses byte-exact IDs; absent or ambiguous local identities remain unresolved. List projections omit descriptions and bound channel/title/thumbnail fields. Current video data is visually distinct from generation-time source snapshots.

Bounds: at most32prompt types,metadata preflight before output loading,2MiB per output,8MiB aggregate outputs,2MiB per selected immutable input,1000items per shape list,5000citation entries and distinct local IDs,5001local rows sentinel. Excesses fail422, never silently truncate. Video walls explicitly show at most48embeds and preserve the full total. Unknown analysis types remain accessible in raw stored-data details.

Validation includes unit shape/alias/bounds checks, isolated MariaDB publication/version/alias/token/case tests, existing core/parity suites and server-rendered media/citation escaping. Actual Opus review packets/results are ignored artifacts under `platform/.local/reviews/event-presentation-*`. Laravel remains the production writer; this slice does not authorize handoff.
