# Group metrics and category trends

This read-only slice ports GroupMetricReport ranking/trend selectors and TagTrendReport date/metric selectors. Generic table.range behavior is unchanged.

- Group ranking/trends exclude the start boundary and include the end; equal endpoints still display that day. Default days=7 yields seven dates, ending today in Taipei. Category trends include both endpoints and default to yesterday, yielding eight dates for days=7.
- days=year and from=year use January 1 as the start boundary. Groups therefore normally display January 2 onward, retaining the legacy January 1 equal-endpoint fallback. Category trends include January 1. Numeric periods are 1–366 days; offsets are 0–3650 days; explicit spans over 366 days fail400 rather than silently truncate. Blank form controls retain defaults; deliberately, category today= blank means the prior-day default, whereas Laravel casts that present blank value to zero (today).
- The legacy explicit-to-only quirk is preserved: missing from derives from shifted current day minus days rather than explicit to, followed by reversed-boundary swapping.
- Group aliases tags_views/views and tags_video/videos select total_views and count_videos. Category views_video selects average. Invalid or repeated selectors fail400.
- Ranking exposes sums, medians, observed days and per-metric known days. Medians deliberately include only recorded values; missing dates/fields are unknown rather than legacy zero fill. Actual zero remains zero; all-unknown results remain null. Seven-day trends follow the same known-value rule. Per-group window coverage is a separate table section, distinguishing withheld source rows from absent caches; metadata excludes unused boundary dates. Arbitrary valid days values remain selected in the form.
- Category average requires paired known views/video counts for every observed row and a positive video sum. Missing calendar dates still make that average partial, disclosed alongside observed-day counts. Cumulative views are not period view growth.
- Category numeric trends never load or budget unrelated tag JSON blobs. Latest cache PK per date is selected before publication checks, so withheld latest rows never fall back to older revisions. Pending/divergent lineage stays withheld. Safe-integer checks protect totals and medians; precision/capacity violations fail422. Group order remains the configured legacy order and overlapping groups cannot be summed as site totals.
- This slice does not generate caches, invoke providers, or change production writers. Existing daily/cloud fallback logic is separate.

Validation: metric-period.test.ts and group-metrics-database.test.ts cover boundaries, aliases, leap years, Taipei dates, explicit-to-only behavior, repeated selectors, null/zero/precision, duplicate revisions and pending lineage. The focused API batch including existing database/report-parity tests passed50/50 with the isolated MariaDB fixture database (no skips). Actual Opus review and resolution are stored under platform/.local/reviews/group-metrics-* (ignored local artifacts).
