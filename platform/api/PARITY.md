# TypeScript API parity ledger

Updated 2026-10-12. This ledger describes **implemented readers**, not production readiness or complete Laravel replacement. `/api/v1/status` lists registered paths only. A 200 response is not evidence of feature parity. All public report data is read directly from MariaDB with parameterized Drizzle SQL; no route proxies Laravel HTTP.

Status definitions:

- **Complete (new contract)**: the explicitly scoped new v1 contract is implemented and tested; this does not imply every legacy option was retained.
- **Partial**: usable report reader exists, but the differences below must be resolved or explicitly accepted before retiring the legacy surface.
- **Pending**: no equivalent reader yet; unregistered `/api/v1/*` returns 501.

## Remaining runtime/behavior risks from third review

- The reader now sets a 5-second MariaDB statement budget, a 3-second acquisition deadline and at most24 outstanding acquisition attempts. Expired late connections are released; server cancellation and queue recovery are covered by real MariaDB tests. These are per-query budgets, not a complete request-wide deadline.
- Active profile/list filtering uses `flag_del IS NULL OR flag_del<1`. All eight historical channel child reports require an existing channel, accept retained archived channels, and expose archive/profile-availability coverage. Unknown IDs404; archived pages retain historical navigation and omit unavailable active-profile links. See [CHANNEL-RETENTION-PARITY.md](CHANNEL-RETENTION-PARITY.md).
- Match/evidence tables have composite keys and the worker replaces evidence transactionally. Separate list/count/coverage SELECTs over mixed legacy MyISAM tables still do not promise a point-in-time snapshot. The API publishes provenance and missing coverage; no claim of atomic cross-table report consistency.
- Error diagnostics intentionally log only validated driver codes plus a static message. Raw driver messages often embed SQL or data, so they remain suppressed; the operator can classify schema faults using the safe error code.
