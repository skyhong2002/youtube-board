### Mandatory stop/drain protocol before each row

1. Record the exact old entries and their dependency/manual callers, last active run, image and current gates. Suspend new triggers for the affected set in the **separate** `youtube-board-scheduler` service and all other entry points; retain unaffected approved jobs only if overlap analysis proves they are independent.
2. Wait for in-flight processes, provider calls, Laravel leases and comment claims to finish or enter an explicitly reconciled interrupted state. ## Stage 4 — rollback and reconciliation

Rollback triggers include identity/authorization failure, unexpected source writes, schema drift, partial publication exposed as complete, provider budget breach, duplicate/uncertain send, failed production account acceptance or the approved load/error thresholds. Stop new triggers first. Disable TS ops/producer execution for affected keys, drain active workers and inspect interrupted journals/claims; env changes alone do not cancel an already-running call. If forced termination is unavoidable, classify every affected run as interrupted/uncertain and do not resume either writer until reconciled.

| Failure point | Reversible action and required reconciliation |
| --- | --- |
| Before public routing / before any TS writes | Remove candidate staging route; preserve diagnostics. Laravel ownership remains unchanged. No restore is needed merely because the candidate failed. |
| Public TS reader/account switch only | Restore approved Laravel ingress/image; apply pre-reviewed maintenance responses to `/auth/*`, `/feeds/u/*`, `/api/ops/editorial*` with private/no-store and sensitive-URL redaction. Preserve account/reader/audit tables; disclose temporary account unavailability. Do not let undefined legacy handlers receive private URLs. |
| After source/cache/AI writes | Capture post-failure DB/journal/queue evidence before any restoration. Preserve valid source/history and widened columns. Classify completed, pending and uncertain writes by business identity; compare MyISAM publication markers and replay only through the reviewed owner. Reconcile comment stage/queue-done and AI snapshot/business-key state before restarting Laravel. Laravel must not blindly consume or overwrite an unresolved TS partial generation. |
| After a Telegram attempt | Freeze both periods in both stacks. Readiness and independently evidenced reconciliation are required even if rolling back only the web. Laravel hourly does not read TS uncertainty tables; slot expiry is not rollback permission. |
| Redis/media loss | Preserve available evidence. Reconcile DB execution IDs before rebuilding Redis queues/tombstones; do not auto-requeue. Missing media may fall back safely; restore consistent manifest/files/cursor and validate identity/hash before refresh. Never remove a stale refresh lock without proving no worker remains. |
| Data corruption requiring restore | Approve a separate maintenance/reconciliation task. Stop every relevant writer; retain an immutable post-incident backup. Restore known-consistent data into an isolated copy first, then reconcile accepted post-backup source/account/editorial changes, quota usage and external deliveries. An old DB backup must not erase evidence that Telegram sent or YouTube quota was spent. Approve the exact data loss/replay scope before replacing production. |

Only after reconciliation and exclusive ownership verification may the **previously approved** Laravel workflows resume. Restore exact prior settings, not a broadened allowlist; verify actual separate scheduler image/env/process and fresh journals. Never operate both writers for catch-up. Immediate application rollback keeps additive schema and compatible widened columns; no automatic down-migration or table deletion.

When TS accounts return, follow the account runbook: normally rotate its session secret, reverify administrator bindings/disabled users and preserve follows/saves/audits. Private RSS tokens are separate hashes; rotating a session secret does not revoke them. Revoke affected RSS tokens only through an approved incident action, retain private-route protection until acceptance, then revalidate with a human.
