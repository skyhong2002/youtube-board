## 第二次修正 release 9ce271a

補資料時發現另外三個問題：

- **關鍵字排名錯誤**：`rankedSubjects` 直接取 `tags_all` 物件的前 N 個 key，但 JS 物件的整數形 key（如 `"14"`、`"2026"`）一定排在最前面。
  結果「前 50 名」裡有 20 個數字，其餘大多是 YouTube、訂閱這類平台詞。
  修正後改依 7 天 `views` 排序，並排除排名頁本來就不顯示的詞（`tagDisplayExclusion`、`tags.no_tag`）；關鍵字 profile 加 `tags` SELECT。
  cache facade 本來就有 `tags` 的權限，所以這次換版不用加權限。
  寫錯的 45 個詞（`urt_show_tag_cloud_tag` 90 筆、`urt_show_video_tag_date` 160 筆，都是當晚才寫入）已刪除，刪除前有備份。
- **關鍵字逐日 `Database operation failed`**：`urt_show_video_tag_date.videos_json/tags_json` 是 TEXT（64 KiB），在 strict mode 下熱門詞一天的資料寫不進去。
  `tools/widen-keyword-day-cache-columns.mjs` 已在正式環境改成 LONGTEXT（160 筆，MyISAM 1 MB），
  備份在 `/home/ubuntu/backups/services/keyword-day-cache-columns-20261020T1644*/`（含 `before-junk-cleanup.sql.gz`）。
- **頻道 7 天文字雲 `Cache source cap reached`**：`cacheVideos` 對全站 7 天（約 3 萬支影片）的文字有 16 MB 上限。
  修正後改為逐日串流，每個頻道各自累加，用的是 tag_date／tag_cloud 同一套 accumulator。
