# 焦點議題「相關影片」設計（2026-11-01）

狀態：2026-11-02 使用者核准並要求直接部署。決定：首頁主數字用頻道數；說明欄參與比對但權重低；時間窗只看當日。

## 實作與原設計的差異（topic-related-v1）

- **讀取時計算，不建表、不加 worker。** 每日 6–8.5k 支影片只比對標題與說明前 300 字，一天約 0.4–0.9 秒；API 程序內快取（過去日期 6 小時、當日 10 分鐘）。因此不需要 migration、授權、worker 映像或排程，只換 web 映像；回滾就是換回舊映像。下面「資料與流程」一節的新表與 `ai.daily.related` 工作暫不做，等規則穩定、需要歷史比較時再考慮。
- 程式：`api/src/reports/topic-related.ts`（純函式 `matchTopics` + 快取）；首頁 `/api/v1/home` 每題附 `coverage`；新路由 `/api/v1/ai/days/:id/events/related?event=&page=`；議題頁「其他頻道相關影片」區塊（`web/src/components/ai/TopicRelatedVideos.tsx`）。
- 校準後的規則（10/30、10/31 正式資料，唯讀）：
  - 標題要有具名人物**且**事件詞；說明欄只加分（只靠說明欄命中會把「加line」之類的詞誤套到別的影片）。
  - 沒有具名人物的議題：兩個事件詞、至少一個在標題、分數 ≥10（避免「國道＋連環車禍」吸進別的車禍）。
  - 同一頻道當日 ≥5 支影片且 ≥80% 標題都有的事件詞視為節目名稱，不計（例：頭家來開講）。
  - 匿名人物（鄭姓男子、網友…）不當人物；當日 >3% 影片都有的事件詞不用。
  - 主要歸屬差距 1.25 倍；同時命中 ≥4 題的標題只列「也可能相關」。
- 10/31 結果：議題 01 AI 6 頻道 → 47 頻道（另 98 支相關）；03 → 39 頻道（58 支）；05 → 23 頻道（26 支）；06 車禍 → 18 頻道（19 支）。AI 引用影片被規則自己命中的比例 16/16（05、06）到 12/25（01，許多辯論影片標題只寫「辯論」）。抽樣看起來大多正確，仍有邊緣案例（例：10/30「德州告 OpenAI 和奧特曼」被歸到鴻海科技日）。
- 尚未做：頻道分類分布條、頻道頭像列、正式的人工精確度標註。

## 目標與非目標

目標
- 每個每日議題附上「其他頻道相關影片」：數量、頻道數、媒體集團數、代表影片與比對依據。
- 讓讀者看到同一件事實際有多少頻道在談，且每支相關影片都能說明為什麼被歸進來。

非目標（第一版）
- 不增加 AI 呼叫，不改 `CHANNEL_IDS`、不改 `urt_ai_date` / `urt_channel_ai` 的內容。
- 不把相關影片混進 AI 引用的計數；兩者分開顯示、分開命名。
- 不做跨日議題合併。

## 做法

### 1. 議題錨點（來自已發布的 AI 結果）

每個議題取：
- 人物：`people`（例如 蔣萬安、沈伯洋）。
- 事件詞：`keywords` 去掉泛用詞。泛用詞用兩道過濾：既有 `shared/tag-noise.ts` / stopwords，加上當日語料的文件頻率（出現在 >3% 當日影片的詞降權，例：市政、選舉）。
- 種子影片：AI 已引用的影片，固定屬於該議題，用來校準。

### 2. 候選影片

- 範圍：所有頻道、議題當日（台北時間 00:00–23:59）發布的影片，約 6–8.5k 支。
- 比對文字：標題為主；說明欄先用 `description-templates` 去掉頻道固定樣板，再取前 300 字，權重較低。
- 比對方式：沿用 `ts_video_tag_evidence` 已存的詞彙命中（tag.observe.tw 詞彙，保留來源與版本），議題關鍵字不在詞彙內時，再對標題做字面比對並記錄為 `literal`。

### 3. 計分與門檻

- 分數 = Σ 命中詞權重（IDF，標題 ×1.0、說明 ×0.4）。
- 收錄條件：至少一個人物（或議題專有地名／組織）**且**至少一個事件詞，分數 ≥ 門檻。只命中人物不收（「沈伯洋」單獨就有 1,973 支）。
- 標題塞滿多個人名的直播（關鍵字堆疊）另設上限，避免一支影片命中所有議題。

### 4. 一支影片命中多個議題

- 依分數排序；第一名比第二名高出 ≥25% 才算「主要歸屬」，只計入該議題的數字。
- 未過差距的列為「也可能相關」，在議題頁可見，但不計入首頁數字。
- 例：「再辯一場」影片同時命中 01、02；含「LINE / 再辯 / 第二場」等 02 專有詞時分數會高於 01，歸 02。

### 5. 校準與品質

- 召回：AI 引用的種子影片，應有 ≥85% 被規則自己命中；不足表示門檻太嚴。
- 精確度：每個規則版本，對前 5 個議題各抽 30 支相關影片人工標註，目標 ≥90%；結果記在 docs 的 release 記錄。
- 規則版本 `topic-related-v1` 寫進每列資料；換規則就重算，不覆蓋舊版本。

## 資料與流程

新表（migration）：

```
ts_topic_related_runs
  daily_pk, rule_version, vocabulary_version, status, counts_json, started_at, completed_at
  PRIMARY KEY (daily_pk, rule_version)

ts_topic_related_videos
  daily_pk, rule_version, topic_key (標題 sha256), video_id, u_id,
  score, is_primary, is_seed, matched_terms_json
  PRIMARY KEY (daily_pk, rule_version, topic_key, video_id)
  KEY (daily_pk, rule_version, topic_key, is_primary, score)
```

工作：`ai.daily.related`
- 在 `worker-ai-daily` 批次內，`ai.daily` 發布後接著跑；沿用同一把 writer lock，不會有第二個寫入者。
- 冪等：同 (daily_pk, rule_version) 已完成則跳過；`--preview` 只印每題數量與抽樣，不寫入；有每次上限與日誌。
- 回補：先 `--preview` 跑最近 14 天，確認數字後再寫入。

## 畫面

- 首頁焦點卡：`AI 引用 26 筆 · 另有 828 支相關影片 / 118 個頻道`，加頻道頭像列。縮圖改從「AI 引用 → 相關影片中觀看最高」依序挑，順便解決影片下架後的空白圖。
- 議題頁：兩個區塊。
  - 「AI 整理依據」：現有內容不變。
  - 「其他頻道相關影片」：數量、頻道分類分布條、影片清單；每支影片可展開看命中的詞（例：蔣萬安 · 辯論 · 交叉詰問）。
  - 「也可能相關」：摺疊顯示。
- 方法說明（MethodNotes）補一段：相關影片是規則比對，不是 AI 判讀，可能有誤判。

## 風險

| 風險 | 處理 |
|---|---|
| 大議題吸走小議題（01 vs 02） | 主要歸屬差距門檻；專有詞權重高 |
| 泛用詞造成誤判 | 當日文件頻率降權 + 必須人物＋事件詞 |
| 標題堆疊關鍵字的直播 | 每支影片最多主要歸屬 1 題；堆疊標題降權 |
| 說明欄樣板 | 先套 `description-templates` |
| 舊日期詞彙版本不同 | 記錄 `vocabulary_version`，回補用當日當時版本 |
