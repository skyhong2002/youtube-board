# YouTube source ingestion in TypeScript

This package ports the YouTube Data API client and the video-statistics, live-polling and tag-upload-backfill workflows from the reviewed Laravel services. It does not enable production jobs, retire Laravel scheduling, or send notifications.

Implemented API methods: channel presence/statistics, uploads playlist page/list, video statistics, duration/caption details, live streaming details, comment threads and comment replies. Calls use only Google's fixed HTTPS API origin. Credential fallback and transient retries are bounded. Error messages and telemetry contain reason categories/status, never credentials, request URLs or provider bodies. Channel presence and live retirement fail closed for malformed response items.

Every actual HTTP attempt precharges one unit atomically in the shared `ingestion_youtube_quota_daily` table, including network failures and retries. Existing Laravel `reserved_units` are counted against the budget and never released or consumed by TypeScript. A crash between charge and request conservatively overcounts. The ledger and client both check the request timeout horizon against the Pacific quota day (including DST); a request cannot intentionally cross midnight. Only `quotaExceeded`/`dailyLimitExceeded` returned for **every configured key** closes the global daily breaker. Rate limits and authentication failures never close it for the day. Do not configure the same request to also settle a Laravel reservation.

Source workflows write history first and advance source freshness last, because the preserved baseline contains MyISAM tables. They do not claim transactional rollback across those tables. One shared TS writer lock serializes source/cache commands; operators must separately stop each corresponding Laravel writer before transferring its ownership gate. Statistics preserve legitimately omitted counts rather than replacing unknowns with zero. Corrupt existing history prevents freshness updates. Live observations preserve malformed items for retry; missing/non-live items retire the live-row entry without claiming why the source is unavailable.

Tag uploads crawl every selected channel until the lower date cutoff or playlist exhaustion, with explicit channel/page/request limits. A truncated channel is not partially published; other completed channels may already have source rows. Cache rebuilding happens only when every selected channel completes. All dates are computed/capped before cache writes. If a later MyISAM write fails, its lineage remains `pending`, exposing interrupted publication. Re-running repairs it idempotently.

The tag cache uses one pinned maintained vocabulary from tag.observe.tw. The rule `youtube-tag-exact-v1-title2-length` uses exact word-boundary/longest-phrase matches, title occurrences weighted twice, description occurrences once, and `log(term-codepoints + 0.5) - 0.5` length weight. It deliberately does not divide by news article counts or reuse news burst scores. `tags_video` and `tags_views` remain separate YouTube metrics. `ts_tag_cache_lineage` records vocabulary version, vocabulary coverage, matching rule, publication state and videos with unknown views. `total_views` is a sum of known observations; unknown counts are not evidence of measured zero.

Commands are provided by the jobs workspace:

```sh
npm run start -w @youtube-board/jobs -- youtube:videos:stats --limit=25
npm run start -w @youtube-board/jobs -- youtube:live:poll --limit=50
npm run start -w @youtube-board/jobs -- youtube:tag-videos:backfill --tagid=102 --days=2 --limit=100 --max-pages=20
```

These default to dry-run and make no YouTube requests or writes. Execute requires `--execute`, `TS_INGESTION_ENABLED=true`, exact entries in `TS_INGESTION_OWNERS`, and runtime YouTube credentials. Production additionally requires `TS_INGESTION_PRODUCTION_ENABLED=true` and exact `TS_INGESTION_WRITE_ALLOWLIST` entries. Workflow keys are `youtube.videos.stats`, `youtube.live.poll`, and `youtube.tag_videos.backfill`. `--max-api-attempts` defaults to 200, including all retries and fallback keys; maximum is 1,000. Tag cache rebuilding requires a published vocabulary and can pin `--vocabulary-version=...`; `--no-cache` explicitly skips that phase.

Channel, duration and comment workflows are now available as documented below. No recurring YouTube schedule or BullMQ activation is installed by this package.

Tests use fake HTTP, so no YouTube quota is spent. `npm test -w @youtube-board/ingestion` runs the API/validation tests. `INGESTION_DB_TEST=1 DB_PASSWORD=... npm test -w @youtube-board/ingestion` additionally checks the isolated loopback MariaDB `youtube_board_test_rewrite`: atomic quota charging, MyISAM publication/idempotence, live logs and complete two-page uploads→source→schedule→tag-cache rebuilding. Integration fixtures are removed afterward.

A final boundary check remains **after** precharge and immediately before dispatch: if the clock advances while the DB call is running, the request is stopped and the charge is conservatively retained. Removing this check to make accounting exact would permit unsafe cross-window requests. Transient network/5xx retries stay on the same key and terminate after the configured limit, matching the Laravel client's behavior; credential/quota/rate failures rotate keys. A provider outage does not automatically multiply transient retries across the entire credential pool.

Integration tests now default to the dedicated `youtube_board_test_rewrite` database. `platform/shared/test-database.ts` rejects the preview database and non-loopback hosts. Tests seed their own vocabulary and source fixtures; existing preview data is not a test dependency.

A client execution also pins its first charged Pacific quota date; a long-running job stops at reset and must restart with a new client/job. This prevents a single run from silently consuming two daily windows. Invalid/missing items use `ts_youtube_item_backoff` with exponential 5-minute through 6-hour delays; polling predicates honor the sidecar without faking source freshness. Explicit single-video commands can retry immediately for operator repair. Aged small batches (statistics: 2 hours; live: twice the configured interval) bypass legacy batch thresholds to avoid starvation. Source DATETIME values are read as strings and interpreted as Taipei wall time.

The exact ownership keys are exported as `youtubeCommands` by `jobs/src/youtube-cli.ts`. `validateYoutubeArguments` checks queue/CLI inputs without I/O. `executeYoutubeWorkflow(args, env, scheduled)` is the worker adapter, returns its result without console output, and checks the scheduled gate when requested. Every CLI execute run records `running` then `completed`, `incomplete`, `skipped`, or sanitized `failed` status in `ts_job_runs`. Unknown/duplicate/conflicting flags fail before database connection.

Channel statistics write validated monthly history and count rows before freshness and preserve hidden subscriber counts. Non-positive view counts and missing items defer the channel: only the failed-attempt `stime` advances, while statistics, history and successful-source `mtime` remain unchanged. This preserves the retirement selector’s evidence of an attempted lookup. Channel retire/restore always requires a successful, exact-ID YouTube presence response. A stale channel alone is not proof it was deleted. Channel upload discovery defaults to one five-item page, matching Laravel. It refreshes every returned item, including old metadata and out-of-order premiere timestamps; weekly cadence uses only the first page’s sample. Explicit extra pages remain bounded discovery, while historical completeness belongs to the separate tag backfill command. Channel-owner mismatches fail before any source writes. Successful publication advances `vtime` last. The two live variants select existing channel taxonomy IDs 52 and 89 respectively; these are distinct from the content vocabulary.

Comment queue selection uses recent view/comment thresholds plus optional channel taxonomy. Completed queue rows prevent automatic duplicate fetching. Comment fetching stages each validated thread/reply page in `ts_comment_stages`; reaching either per-run page cap preserves the exact continuation (including a partially crawled reply thread). Public `urt_comment` is updated only after thread/reply exhaustion, with author profile and reverse-video index publication first. A crash during nontransactional legacy writes leaves the sidecar `publishing`, and replay repairs the same queue generation. Existing published caches survive incomplete/invalid scans. Staged JSON defaults to a 12 MiB bound, configurable with `--max-state-mib=1..64`. A capacity limit returns a resumable `capacityBlocked` result, preserves the prior checkpoint and claim release, and can be retried with a reviewed larger bound; it does not permanently quarantine the video. This is not a complete historical comment archive: YouTube can remove/edit comments during pagination. There is no claim of a provider-transactional snapshot.

Migration `007_source_counts_and_comments.sql` widens legacy source/history/live/duration/comment counters to signed BIGINT and author display names to VARCHAR(512). It preserves existing values/nullability, never clamps counts, and TS continues rejecting values outside exact JavaScript safe-integer range. Production adoption needs an approved backup, estimated ALTER locking/disk cost, and the usual writer handoff. Do not roll these columns back to INT once larger values exist; rollback uses the previous application image with widened columns, or a verified backup. Only the isolated test database has had this migration applied here.

TVBS-specialized uploads/live tables and derived cache workflows are implemented by the cache slice. Scheduled activation, production migration, and source ownership handoff still require the documented operator gates; no new recurring schedule is enabled automatically.

The Opus source review added several important edge cases. Real reply IDs may contain dots; identity validation retains exact bytes and verifies `snippet.parentId`. Resource-specific errors (for example disabled comments or a missing uploads playlist) defer that item without aborting unrelated items. Quota/auth/rate/network failures still stop execution. Zero-second duration observations remain retryable because a live/upcoming video may acquire its final duration later. Retire presence checks also use per-channel backoff so a still-present stale channel cannot monopolize the queue. Upload scheduling uses the first page’s weekly sample, and minimum delay is applied before the Taipei morning rule. Live-tag discovery (52/89) sorts by `vtime` without excluding future values, matching Laravel’s frequent live scan.

Comment stages publish only authors retained in the final comment tree. Full snapshots are saved at thread-page boundaries and reply checkpoints rather than after every ordinary thread. The database requires `max_allowed_packet >= (max-state-mib + 1) MiB` (13 MiB for the default 12 MiB stage); preflight checks this before provider calls. Successful stages are deleted after queue completion; an interrupted published generation can replay or be replaced by a new queue generation. Failures use bounded backoff without an unreachable twelve-failure cutoff. Explicit `--videoId` retries remain available after any number of failures, while active queue claims remain protected. Explicit repair uses `youtube:comments:reset --videoId=ID --execute` under the separate `youtube.comments.reset` ownership/allowlist gate: it archives the old stage in `ts_comment_stage_archive`, then resets the stage/backoff and explicitly requeues a completed source video when necessary. Public caches and done history are preserved; active or unfinished claimed rows cannot be reset. Archive retention/deletion requires an explicit maintenance workflow; no automatic evidence deletion is installed.

Schema assumptions checked against `migrations/000-legacy-dashboard-baseline.sql`: channel/count `viewCount` already use signed nullable BIGINT; channel monthly values are JSON in `urt_log.thedata`; `urt_video_duration.pk_video` is its own AUTO_INCREMENT identity (not `urt_video.pk`). Migration 007 preserves the checked baseline's signedness, nullable flags and NULL defaults. The exported `assertSourceCountSchema` preflight rejects incompatible defaults, nullability, unsigned/zerofill types and generated columns before any migration 007 ALTER. The local migrate command invokes it; future production adoption tooling must call the same preflight. Writer connections additionally set `STRICT_ALL_TABLES` so narrowing/truncation errors fail closed. A hidden subscriber observation with positive channel views intentionally preserves the historical numeric column for Laravel compatibility while recording `hidden: true` in monthly source history.

The second source review also hardened partial-run accounting. Upload/comment jobs stop cleanly on a global API failure/cap and return their already-applied rows, `stoppedReason` and remaining count; these are persisted in run history rather than lost to a bare exception. Execute results include `executionKey` for BullMQ-to-DB correlation. `youtubeResultState` distinguishes failed items/provider stops from normal incomplete batch coverage. Comment continuation uses `checkpointed` and returns a normal CLI exit; queue truncation uses the same incomplete status. Queue-done primary-key collisions with a different video are rejected before publication. Upload ownership is checked for every video before any source write. Resource-specific batch failures in channel statistics/presence checks defer the batch without falsely retiring a channel.

Validation after babysit round 2: focused ingestion suite 47 passed with `INGESTION_DB_TEST=1`, plus 7 focused jobs tests with `JOBS_DB_TEST=1` (argument validation, scheduled gates, strict SQL session, migration preflight, shared Laravel locks and status semantics). Typechecks pass for both workspaces. Four completed `claude-opus-5-5` reviews informed the fixes; fixtures use fake HTTP and the dedicated isolated test DB with cleanup. Channel discovery accepts non-monotonic publication times, and comment cursors may advance through empty pages. Repeated cursors and mismatched resource identities still fail closed. No production parity claim is made.


Babysit round 2 aligned the source behavior with Laravel more closely. Comment selection/claiming requires `ftime IS NULL` and a null or at-least-30-minute-old `stime`, including explicit video requests. Every page boundary renews the claim using compare-and-set; partial/error paths restore the prior claim marker, and completed history retains the actual renewed claim time. Comment defaults are one thread page (maximum three), twenty reply pages (maximum one hundred), with a ten-video execute cap. Comment queue execute is capped at twenty. Legacy duplicate author ChannelIds use the oldest existing author row, and blank or empty-object reverse indices are accepted as empty lists. Provider snapshots may contain more embedded replies than their stale reported count.

Source execution still requires stopping the corresponding Laravel writer before handing ownership to TypeScript. For production, `TS_LARAVEL_LOCK_STORE=database` uses Laravel’s `cache_locks` owner/expiration protocol and requires the exact `TS_LARAVEL_CACHE_PREFIX` (including an explicitly empty prefix if that is the configured value). This must match the Laravel command’s actual cache store; a database lock cannot interoperate with Laravel’s file-cache lock. When the old writer uses file locks or has been retired, `TS_LARAVEL_LOCK_STORE=stopped` records the operator’s explicit writer-stop handoff instead. Neither setting changes production by itself, and no ownership transfer was performed here. Shared database locks expire after fifteen minutes, matching Laravel, renew at writer boundaries and never delete a replacement owner on release. Release failures preserve the original workflow error.

A pre-existing Google daily breaker yields distinct `quota-exhausted`: untouched runs are skipped; runs with applied rows, checkpoints or newly enqueued durations are incomplete. Item failures retain failed status even when a separate capacity limit is also reached. Attempt-budget limits remain separate. If storing a new Google breaker fails, the original `quota-daily` exception survives and the client’s in-memory breaker prevents further requests. Source clients also honor the worker shutdown AbortSignal before quota charging and while fetching.

Uploads results expose actual `apiItems`, `pages`, ISO-UTC `oldestPublishedAt` and `pageExhausted` for source-first AI coverage checks. These describe the bounded response, not a complete historical snapshot. Batch item rejection advances only the selected statistics/duration retry marker and sidecar backoff. Duration enqueue provenance survives global provider stops.

The follow-up Opus review confirmed the round-2 fixes and bounded coverage fields. Its additional findings now preserve duration enqueue provenance on unexpected request failures and `partialVideos` after interrupted uploads publication, while statistics failure backoff rechecks ownership. An empty validated channel-ID batch is handled locally without provider calls.

## Derived caches and remaining source workflows

`jobs/src/cache-cli.ts` now owns capped, dry-run-first builders for counts, predictions, schedule timing, taxonomy/people dates, closed-month rollups, channel/tag/keyword clouds, keyword relations, `tags_all`, live display rows, live tag-date/hour buckets, archived legacy cache cleanup, stale-live retirement and Wikipedia photo URLs. `cacheCommands`, `cacheFields`, `validateCacheArguments`, and `executeCacheWorkflow(args, env, scheduled)` are the CLI/worker contracts. They share the same writer lock as source ingestion and require the **exact** ownership, execute, production and scheduled gates. No production ownership or schedule is activated by their installation.

```sh
npm run start -w @youtube-board/jobs -- reports:counts:build --limit=20
npm run start -w @youtube-board/jobs -- reports:tag-date:build --tagid=102 --from=2026-10-01 --to=2026-10-11
npm run start -w @youtube-board/jobs -- reports:tag-cloud:build --tagid=102 --days=7
npm run start -w @youtube-board/jobs -- reports:channel-cloud:build --u_id=8 --days=7
npm run start -w @youtube-board/jobs -- reports:keyword-cloud:build --subject=台灣 --days=7
npm run start -w @youtube-board/jobs -- reports:keyword-relations:build --subject=台灣 --days=7
npm run start -w @youtube-board/jobs -- reports:tag-month:build --tagid=102 --subject=台灣 --month=2026-09
npm run start -w @youtube-board/jobs -- reports:keywords:cache
npm run start -w @youtube-board/jobs -- reports:live-tag-date:build --tagid=102 --days=2
npm run start -w @youtube-board/jobs -- reports:photos:build --terms=台灣,臺北市 --limit=2
npm run start -w @youtube-board/jobs -- reports:channel-predictions:build --u_id=8
npm run start -w @youtube-board/jobs -- youtube:tvbs:videos --u_id=8 --days=7
npm run start -w @youtube-board/jobs -- youtube:tvbs:live:poll --stale-seconds=40
```

Calendar periods use Taipei midnight boundaries. Current-day rows are **observed snapshots**, not claims of a complete day: lineage records `window_from`, `window_to`, `window_closed`, and `generated_at` as the observation cutoff. Future periods are rejected. A monthly cache accepts only a complete, closed calendar month and requires every source day to have matching published vocabulary version, coverage, rule, and no unknown view observations. Missing days prevent publication. Cloud identities always refer to the canonical current calendar window; `tags_all` fixes its identity to seven days and taxonomy OR `1,2,13,14`. Keyword-relation cache identity is global and refuses channel filters. `reports:people:build` rebuilds full maintained-vocabulary day buckets for taxonomy 13 by default, replacing repeated partial per-person updates; local `tag_group` still determines display membership.

`ts_report_cache_lineage` and `ts_live_tag_cache_lineage` expose pending/published state, vocabulary lineage, unknown counts and period coverage. Readers hide pending/unknown snapshots; the legacy API and v1 cloud/live/tag readers use the same key normalization. A process crash can leave a MyISAM row and its sidecar pending; replay repairs it. Run history records pending generic publication keys on failure. Source rows are capped before publication and text is bounded to 16 MiB per selection, 16 MiB prepared date batches, and 8 MiB per published payload. Limits fail closed. These caps do not prove that captured source data contains every YouTube video; upstream capture coverage remains distinct from local cache completeness.

Counts clear insufficient/hidden deltas to NULL, keeping measured zero distinct. Count and prediction scans rotate via a separate work-state table. Predictions preserve the existing seven-day seasonal interpolation and 10-million-per-day outlier rule; they update prediction columns without advancing source freshness. Schedule rebuilding records the inspected source stamp separately and changes only `stime`, avoiding a falsely fresh `mtime`; an explicit `--videoId` retries a repaired source stamp. Wikipedia images use only a fixed public pageimages endpoint, no redirects, a one-MiB response cap and 15-second timeout; only HTTPS `upload.wikimedia.org/wikipedia/` URLs are stored. Missing images preserve any previous cache. Explicit terms bypass dictionary selection but not execution gates. Automatic selection uses the maintained vocabulary and skips usable cached images.

TVBS uploads select channel taxonomy 29, preserve the same bounded full-crawl/source ownership safeguards, and publish live candidates only to `urt_video_live_tvbs`. TVBS polling uses the independent TVBS daily log and a default 40-second staleness interval. No real YouTube or Wikipedia requests were made in tests.

Migration 008 adds lineage/work-state/archive tables and widens reviewed nullable counters and JSON text. `assertReportCacheSchema` runs before its ALTER statements and rejects nullable/default/signedness/charset/collation drift. Migration verification used isolated test fixtures; local preview schema adoption is handled separately. Production adoption still needs reviewed locking/disk estimates, backup, rollback plan and source-writer handoff. `reports:live:clean` archives the exact legacy row before deletion, rechecks its invalidation predicate, and excludes any row with TS live lineage. Archive removal is not automatic.

Six obsolete jobs are explicit retirements rather than fake runnable workers; see `CACHE-PARITY.md`. In particular, group-view requests now prefer dynamic published source projection; an imported `urt_show_group` envelope is returned only when live source cannot be projected and is labeled a historical snapshot with unknown period coverage. `reports:groups:build [--group=NAME] [--hours=22] [--limit=20] [--offset=0|auto] [--execute|--dry-run] [--json]` implements the normal Laravel read-only local status path, with total/active/deleted tag rows, bounded group rows and latest observed membership timestamp. It reports `mode: read-only` with the original request in `requested_mode`, and performs zero data writes and no external calls, including with `--execute`; hours/offset are explicitly labeled compatibility-only fields. It is CLI-only, never a queued maintenance writer. Ongoing optional external membership sync is explicitly unsupported: the new full term snapshot does not include group membership, and terms must not be guessed into groups.

Jobs/API typechecks pass. Two completed Opus 5.5 reviews informed fixes for lock-loss propagation, null delta semantics, canonical/cache period identities, closed daily/monthly lineage, source caps, partial publication, source freshness, photo retry rotation, and stale predictions. `test/fixtures/channel-prediction-php.json` was generated from the original Laravel private `dailyPredictions` method using its loaded PHP/Carbon dependencies in an ephemeral network-disabled, read-only container (no database). It covers missing observations and an ISO year boundary. Sixteen cache ownership keys plus the two TVBS source variants are implemented; the full 45-job ledger separates the implemented read-only group report from unsupported legacy remote membership sync.

Photo negative observations are separate successful outcomes. Automatic selection rotates attempts and honors a seven-day no-image cooldown or bounded exponential failure backoff; explicit terms are an operator retry. Photos take a dedicated writer lock so network timeouts do not block YouTube source capture. Prediction data unavailability clears prediction columns to NULL and is reported as incomplete coverage; malformed histories are errors. Repeated dates/months are rejected rather than allowing older records to overwrite newer observations.
